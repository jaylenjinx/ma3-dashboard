For grandMA3 & grandMA2 onPC

MA3 Dashboard

One window for every onPC version on your computer. Launch the one you need, find your showfiles, manage themes, fixture types and datapools, install new releases, and keep it all in sync between your Mac and PC.

Download for Mac Download for Windows Source on GitHub

Free · macOS 14 or later (native SwiftUI) · Windows 10/11, 64-bit (no .NET install needed)

What it does

onPC spreads itself across launcher slots, standalone apps, per-version data folders and a shared library. The dashboard reads all of it and puts it in one place.

Launch any version

Every installed build, from launcher slots like 2.2 to 2.4 to the standalone 2.5 apps, plus grandMA2. It shows which one is running.

Showfiles per version

Each version's shows and backup count, sorted by date. Duplicate, import, reveal, or send LoadShow to a running console over OSC.

Color themes

Every theme drawn as a mini sequence sheet in its own colors, with the full color list one click away.

Fixture types

GDTF, MA3 XML and MA2 pxml in one list, with manufacturer, DMX modes, channel counts and revision read from the files.

Install new versions

Finds onPC installers in Downloads, tells you which are new, and installs them with one click.

Cloud Sync

Shows and library files sync between computers through a small server you host yourself. Mac and Windows share the same server.

Every version, one list

grandMA3 2.5 and later install as their own apps. 2.4 and earlier live as slots inside the grandMA3 launcher, which starts whichever slot was used last. The dashboard finds both kinds and launches the exact build you pick. It switches the launcher's slot for you when needed.

When two builds share a data folder (2.5.1.0 and 2.5.1.1, say), the Launch button starts the newest one and its menu lists the others. grandMA2 gets the same treatment, including its CleanStart build.

With a show open and OSC input on port 8000, Load sends LoadShow to the running console. Switching shows doesn't mean leaving the dashboard.

Library managers

The shared gma3_library (and each version's own) shown as something you can browse. Drop files on the window to import them, and duplicate, reveal or bin what you don't need.

See a theme before you load it

Each card draws a sequence sheet (header, cues, the selected row) in the theme's own colors, so you can tell dark from default_legacy at a glance. Select one to see every color group with its RGBA value.

Themes made with MA3 Theme Builder show up here as soon as they're saved to the library.

GDTF, MA3 and MA2 together

The dashboard opens each GDTF file and reads its description, so the list shows the real manufacturer, name, revision and every DMX mode with its channel count. MA3 XML types are read the same way. MA2 .pxml files are listed by filename.

Filter by format or search across manufacturer, name and filename.

Everything you've exported

Presets, plugins, macros, sequences, MAtricks and the rest, read from the exported XML: object type, preset mode, plugin version and author, and the data version it came from.

Plugins show their Lua source right in the window. Old .bak copies left over from plugin development stay hidden until you ask for them.

Cloud Sync

Keep showfiles, color themes, fixture types and datapools the same on every computer you program on. The server is a single file with no dependencies. Run it on anything that runs Docker, and reach it over a Cloudflare Tunnel so no ports are open.

  • Safe by default. If a file changed on two machines, both copies are kept. Deleted or overwritten files stay in the server's history.
  • Patient with onPC. A show saved in the last 15 seconds waits for the next sync, so a half-written file is never sent.
  • Big shows are fine. Uploads go in 16 MB chunks, under Cloudflare's 100 MB request limit.
  • Mac and Windows together. Files are stored by product and version (ma3/2.5.1/shows/…), not by path, so a show saved on the Mac lands in the right folder on the PC.

Set up with Portainer

  1. In Cloudflare Zero Trust, create a tunnel with a public hostname pointing at http://sync:8787, and copy its token.
  2. In Portainer, go to Stacks → Add stack → Web editor and paste in portainer-stack.yml.
  3. Add the environment variables SYNC_TOKEN (any long random string) and TUNNEL_TOKEN.
  4. Deploy, then enter the hostname and token under Cloud Sync in the app.

The stack uses the stock node:22-alpine image with the server built in, so there's nothing to build or pull from a private registry.

Or with docker compose

cd sync-server
cat > .env <<EOF
SYNC_TOKEN=$(openssl rand -hex 32)
TUNNEL_TOKEN=<from Cloudflare>
EOF
docker compose up -d --build

For LAN-only use, drop the tunnel service and publish port 8787. The full setup and API are in the server README.

On Windows too

The Windows version has the same pages, built with .NET and Avalonia. It ships as a single MA3Dashboard.exe that doesn't need .NET installed. It runs MA's own installers, which ask for administrator access themselves, and keeps the sync token encrypted with Windows DPAPI.

grandMA2 onPC runs natively on Windows, so it gets the same launch, CleanStart and showfile handling. A Mac and a PC can share one sync server.

Install

Download the build for your computer from the latest release.

Mac

  1. Unzip MA3-Dashboard-mac.zip and drag MA3 Dashboard to Applications.
  2. The app isn't notarized, so the first time, right-click it, choose Open, then Open again.
  3. To let it list installers in Downloads, allow access when macOS asks.

Windows

  1. Unzip MA3Dashboard-win-x64.zip anywhere, for example C:\Tools\MA3Dashboard.
  2. Run MA3Dashboard.exe. If SmartScreen warns about an unknown publisher, choose More info → Run anyway.
  3. The sync-server folder next to the exe holds the server setup files.

Build it yourself

# Mac (Swift 6, Xcode command line tools)
./build-app.sh            # → build/MA3 Dashboard.app
./build-app.sh --install  # also copies it to ~/Applications
# Windows (.NET 10 SDK, on any OS)
cd windows
./publish.sh              # → dist/MA3Dashboard-win-x64.zip
